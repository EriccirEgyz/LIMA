# SFT 数据筛选与轨迹配比

`mix_sft_by_trajectory.py` 按各来源的**轨迹数量**抽样，合并已经转换好的 Alpaca SFT 数据。只依赖 Python 标准库，不加载模型或 tokenizer。

## 处理顺序

1. 用 `src/traj/rollout_to_sft.py` 转换原始 rollout，完成现有轨迹筛选和目标轮 HIDE 等处理。
2. 如果实验需要完整样本长度筛选，用 `src/select/filter_sft_by_length.py` 分别处理各来源。
3. 用本目录的混合脚本，从最终候选池中抽取指定数量的轨迹。

混合脚本只选择与合并，不改写 system、history、output、reasoning 或工具调用，也不会恢复已被清洗隐藏的监督目标。训练仍需沿用转换器要求的 `mask_history=true`。

这里“一条轨迹全部选中”指纳入这条原始轨迹**在输入 SFT 文件中仍然存在的全部有效切片**，不要求把长轨迹拼成一个训练样本。被长度筛选删去全部切片的轨迹不可用；只删掉部分切片的轨迹仍算一条。先统一各来源的清洗/长度策略，再抽样，才能保证最终轨迹配比；混合后进一步过滤可能改变配比。

## 命令行接口

在 LIMA 根目录运行，或使用绝对路径。所有相对路径相对于当前工作目录。

```bash
python -B src/select/mix_sft_by_trajectory.py \
  --source data/sft/dag_s/dag_s_sft_v3.json 50 \
  --source data/sft/spbench_route1/spbench_route1_sft_v2_32k.json 50 \
  --seed 42 \
  --out data/sft/dag_mix/dag_s50_dag50_seed42.json \
  --dry-run
```

`--source SFT_JSON COUNT` 可重复多次，COUNT 是正整数轨迹数；只传一个来源也支持纯来源对照。无需传入来源名称，统计和审计标签自动使用真实文件名（去掉 `.json`）；不同目录有同名文件时自动使用完整路径区分。标签不参与抽样。示例用 route1 展示接口，实际 DAG 池可以替换。上述两个现成文件并不表示已经使用一致的长度过滤策略；DAG-S v3 尚需按实际实验配置确定是否过滤。

`--dry-run` 会完整校验输入、执行抽样并打印可用/选中轨迹数、选中切片数及两种占比，不创建输出目录或文件。去掉它才写盘。正式写盘时会创建缺失的输出目录。

| 参数 | 含义 |
| --- | --- |
| `--source SFT_JSON COUNT` | 必填，可重复；文件路径和所需轨迹数 |
| `--seed` | 默认 42；随机种子记录到审计输出 |
| `--out` | 必填，输出 `.json` 路径；三个输出文件都必须不存在，dry-run 也检查冲突 |
| `--dry-run` | 只校验、抽样和打印统计 |

候选轨迹恰好够用时全部保留，多于请求时无放回随机抽取，不足时汇总缺口并退出（退出码 2），不重复采样、不生成部分混合数据。例如：

```text
轨迹数量不足（不会重复采样或写出文件）:
dag_s_sft_v3: 请求 60 条，清洗后可用 55 条，缺 5 条
```

轨迹 1:1 不等于切片或训练 token 1:1。本程序报告轨迹与切片占比，不将字符数伪装成 token 数，也不估计实际 loss 权重。

## 输入与分组约定

输入是现有转换器输出的 JSON 数组，包含 `instruction`、`input`、`output`、`system` 字符串及 `history` 字符串对列表。每个输入必须有同名相邻文件，例如：

```text
dag_s_sft_v3.json
dag_s_sft_v3.manifest.jsonl
```

若输入是软链，先解析真实 JSON 路径，再寻找其旁边的 manifest。首版不提供独立 manifest 路径参数；转换时使用了自定义 manifest 名称的数据，需准备满足此命名约定的一对文件。

分组沿用转换器和长度筛选器的契约：按 manifest 行顺序，每行的 `n_samples` 对应 JSON 中接下来的连续切片；`kept` 必须是与 `n_samples > 0` 一致的布尔值。所有行的切片数之和必须等于 JSON 实际长度。空行忽略，审计中的行索引按非空记录从 0 开始计数。

**必须配套使用同一次转换/筛选的两个文件，不要事先打乱 JSON。** 旧 JSON 没有逐样本轨迹 ID，单靠数量无法识别所有“样本数相同但排序被修改”的错配。程序拒绝缺失 manifest，绝不退回按 SFT 行抽样。

原始轨迹身份使用 `(manifest.source, task_index, sample_idx)`，不单独使用任务级 `global_id`。不同原始来源可以有相同任务索引或 global_id；同一原始轨迹在一个 manifest 内重复，或在多个来源中同时被选中，会报错。重复输入路径（包括软链/硬链）及内容完全相同的输入 JSON 也会报错。

不同转换版本若来自同一原始轨迹，其身份相同，不能在混合中重复计数。重叠检查不通过时应先明确互斥候选池，不会自动重抽而悄悄改变抽样分布。它不做语义去重，也不能识别所有被改写原始来源标识的重复轨迹。

## 抽样与输出顺序

每个来源分别初始化 `random.Random(seed)`，对可用轨迹索引生成随机排列，再取 COUNT 条。各来源不共享随机数状态，文件名和路径都不参与 seed。在相同 Python 版本、输入内容与顺序下：

- 同一 seed、同一配额重复运行，选择相同。
- 改变其他来源的顺序或配额，不影响这个来源的选择。
- 重命名或移动配套的 JSON/manifest，不影响选中的轨迹。
- 同一来源增大配额时，较小配额选中的轨迹仍然保留，便于比较不同配比。

选中后按命令行来源顺序、各来源原 manifest 顺序导出，轨迹内部切片顺序也保留。导出时不单独打乱切片，以保持 manifest 连续分组契约；训练阶段可正常使用数据加载器的 shuffle。Python 版本和源文件 SHA-256 均记录到统计文件。

旧版的 `--source NAME SFT_JSON COUNT` 已移除，使用新接口时删掉 NAME 即可。抽样算法也从名称派生 seed 改为直接使用 seed，因此旧版与新版在同一个数字 seed 下的入选子集可能不同；统计文件的 `sampling` 字段记录使用的规则。

程序逐条读取并检查所有输入样本，只在内存中保留入选切片；内存用量随选中数据规模增长。抽取全部数据时仍需能容纳全部选中切片的内存。

## 输出

假设 `--out .../mix.json`，生成：

| 文件 | 内容 |
| --- | --- |
| `mix.json` | 选中切片的 Alpaca JSON；字段值原样保留，不注入训练元数据 |
| `mix.manifest.jsonl` | 每条选中轨迹一行；原始审计字段保留，新增/追加 `trajectory_mixing` 记录 |
| `mix.mixture.json` | 来源路径与 SHA-256、随机种子、Python 版本、配额、可用与选中数量、占比、选中轨迹 ID 和范围 |

`trajectory_mixing` 最后一个元素描述本次混合，记录来源名称、输入文件、输入 manifest 行索引、输入/输出切片范围和 seed。范围均从 0 开始、左闭右开。更早的混合记录以及原 `length_filter` 字段是此前步骤的审计，其范围不表示当前混合文件位置。

输出 manifest 可继续被 `filter_sft_by_length.py` 使用，也可作为下一次轨迹抽样的输入。这里只输出选中的轨迹；未选中/不可用轨迹仍在源 manifest 中，统计文件保存源 manifest 哈希供追溯。

所有输入校验完成后才开始写出。默认拒绝覆盖任意一个输出文件，不提供 `--force`。正常写入异常时清理本次新建的部分文件，不删除预先存在的文件；这不是跨三个文件的事务，进程被强制终止或机器断电后需检查是否有残留输出。

生成混合文件不会自动注册 LLaMA-Factory 数据集、修改训练 YAML 或启动训练。
